# 单机 RACER 规划器优化交接 · 2026-11-19

接手分支为 `codex/planner-observable-stops`，规划器提交为 `397cbef`，对照基线为 `5d4db01`。本轮改动集中在单机停车后如何为下一次观察选择前沿视点。Depot 07 单次闭环中，原生规划耗时中位数从 31.35 ms 降到 14.81 ms，首次到站观测提前 4.00 仿真秒。首次可靠人员测位晚了 27.00 仿真秒，两版都运行到 180 秒预算上限。

## 改动从哪里接手

- **候选生成与打分**在 [frontier_steps.hpp](../tools/flight/frontier_steps.hpp) 的 `refine`。保留 1.6 m 以内的原巡游目标。更远的目标先尝试同一前沿的 RACER 原生视点和航向，再尝试 0.6–1.6 m 的分段观察点。用当前体素图检查直达航段净空，按相机视锥内有无遮挡视线的有效前沿样本数排序，同分优先选预计平移和转向耗时较短的点。
- **重复目标抑制**在同一文件的 `ReplacementHistory::accept`。候选距上次替换目标不超过一个体素、且飞机距上次出发点不足 0.6 m 时，沿用原巡游目标。原地重复提案不会刷新这条记录。
- **接入 RACER**由 [frontier_steps_overlay.py](../tools/flight/frontier_steps_overlay.py) 在构建时完成。仿真中，单机停稳后规划下一段普通探索航迹，且尚未选中语义方位视点时，才尝试替换目标。候选未能生成原生轨迹时，重新规划原巡游目标。执行器继续检查实际轨迹、净空和末端制动。改动入口与测试分别见[策略说明](../tools/flight/FRONTIER_STEPS.md)、[几何测试](../tests/frontier_steps_test.cpp)和[构建接线测试](../tests/test_frontier_steps.py)。

## Depot 07 闭环实测

基线、初版和最终版在同一台 WSL 运行机各跑一次，使用相同场景、起点、检测权重及 180 仿真秒预算，均开启 RViz。初版 32 次提案中有 16 次被拒，最终版在相同提案数下减至 8 次。原生规划耗时取提案事件的墙钟时间，任务里程碑按仿真时钟计。

| 指标 | 基线 | 最终版 |
|---|---:|---:|
| 原生规划耗时中位数 / P95（ms） | 31.35 / 42.00 | 14.81 / 28.73 |
| 首次原生航迹激活（s） | 65.70 | 66.22 |
| 首次到站并取得新观测（s） | 71.20 | 67.20 |
| 首次可靠且匹配人员位置的表面测位（s） | 120.50 | 147.50 |
| 同一来源完成视觉确认和匹配测位（s） | 预算内未达到 | 152.50 |
| 原生提案 / 被拒 / 安全制动（次） | 22 / 6 / 4 | 32 / 8 / 6 |
| 激活航段 / 完成到站观测（次） | 16 / 15 | 24 / 23 |
| 结束时已观测体素 | 12,146 | 11,710 |
| 运行器墙钟耗时（s） | 437.1 | 436.8 |

人员匹配仅在运行后按水平误差 ≤ 0.65 m 评分。最终版更早完成首次到站观测，也在预算内取得同一来源的双项证据。单场结果尚不足以判断平均任务完成时间。冻结地图回放另检查了 50 份历史拒绝快照，在 180 对有候选的前沿中，同时通过直达净空预筛且至少有 3 个可见样本的数量从 49 增到 58。这批快照集中在拒绝时刻，且没有连续的选点历史。

1. 在团队 WSL 运行机分别检出基线和最终提交。每版按 [Depot 07 构建与运行命令](../README.md#复现-depot-07-联调)在独立目录构建原生 RACER，传入 `--execution-safety --consistent-inflation`。将对应构建目录交给 [run_depot07.sh](../tools/flight/run_depot07.sh)，每次指定新的输出目录。两版都启用 `ASPIRE_FRONTIER_STEPS=1`，基线使用该提交当时的选点算法。启动后确认 RViz 已显示场景和轨迹。
