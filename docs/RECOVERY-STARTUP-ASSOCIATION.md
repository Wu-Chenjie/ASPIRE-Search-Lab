# Stage32：恢复时效、启动前置与可靠空间去重

2026-10-17 UTC。活动源码为本目录，Stage31及全部失败原件冻结。实际结果以[Stage32报告](../../task-3-evidence/stage-32-recovery-startup-association/RESULTS.md)、[检查点](../../task-3-evidence/stage-32-recovery-startup-association/PROGRESS.md)为准。保存开发回放不等于新飞行，双源ROS不等于双机飞行。

## 1. 输入与推理调度

Stage31定时回调既处理推理，又依赖另一ROS线程消费时钟/传感器；仅按回调开始clock节流会挡住同一clock稍后到达的新RGB或几何。Stage32在decoupled/registry模式中使用单ROS接收线程和单感知工作线程：

~~~mermaid
flowchart LR
 I[ROS接收: RGB-D 标定 位姿 TF 时钟] --> Q[原40时刻输入缓存与PoseHistory]
 I --> W[合并Event: 最多一个待处理唤醒]
 T[原0.2sim秒timer: 状态过期唤醒] --> W
 W --> P[单感知worker: 快照与最新有效采集]
 Q --> P
 P --> V[视觉存在]
 P --> G[独立合格表面]
 V --> C[C++原生源记录与可逆空间对应]
 G --> C
 C --> R[原生RACER与原执行授权]
~~~

新RGB消费间隔按**采集时间**至少.2sim秒选择；同一RGB已缓存的晚到几何可立即完成，不重复检测/累计视觉支持。输入触发合并，不排无限任务；timer在无输入时继续使状态过期。旧hybrid/strict/legacy保持原2线程执行方式。工作线程退出后才关闭证据和ROS发布器；运行错误由ROS timer转为进程失败，不能悄悄停止感知而继续声称健康。

原max_frame_age=.75sim秒和.75墙钟接收后年龄、未来采集容忍、40ms位姿插值括号、精确采集TF/标定检查不放宽。新增process_calls真实累计、callback开始/耗时/间隔、队列最新时间、推理和表面阶段状态；实际到达/独立消费频率分别报告，名义timer频率不是吞吐测量。

## 2. 合格历史与当前点分离

同源可靠位置仍需至少3份真实合格表面、跨度≥.8秒、窗口≤2秒、最大离散≤.25米，原不确定度半径检查保留。Stage31把一次过期处理或“深度跨度过大、没有合格点”视为需要抹去全部支持，隐含了未声明的连续成功要求，导致间歇测量饥饿。

Stage32对此两种“没有新合格测量”立即清空当前XYZ，但保留仍受原2秒窗口约束的既有合格样本；新鲜合格测量到来后重新检查全部原门限。拒绝帧自身不进入支持、不更新时间来延寿。真实位置矛盾、关联不可靠、其他无效几何仍可清空支持。窗口过期不能借旧样本凑3帧，历史点仍只作history_only。

视觉确认仍与定位分开；原≥.70、5个不同RGB时刻、跨度≥.8秒等门不变。可靠3D点不作为确认人数凭据，定位失败不撤销RGB历史。

## 3. 紧凑可见表面

源8残余重复的保存帧审计表明它确为原人体，52次观测中45次因整个连续表面跨度超过.35米而拒绝。仅放宽跨度会增加背景污染，本轮保留原.35米门，加入紧凑表面提取：

1. 原腐蚀掩膜、有效深度范围、.12米4连通深度组件、主组件/核心支持/竞争拒绝先行。
2. 若主组件90%深度跨度>.35米，寻找宽度≤.35米的最大支持深度区间。
3. 该区间须覆盖原主组件至少80%，且继续满足原最少像素、相对全部有效像素的主组件比例、核心支持比例。
4. 对保留区间继续按原分位数跨度、三维尺寸与不确定度检查；无占优紧凑区间仍拒绝。

这是局部可见表面代表，不是人体中心或稳定解剖点。没有新增模型、ReID或从已知人数凑关联。C++对应仍要求可靠点/静态锚点、唯一空间候选、原cost/gate、坐标版本及共存排斥；没有改成仅凭射线强合并。源记录的本地富状态增加association_reason、identity_state和明确历史锚点，摘要协议不附带这些本地调试字段。

保存开发回放的5个确认源最终1假设、近邻2个保持2个，仅说明该开发例的残余重复被可靠锚点解决。新22个组件和3个融合输出的网格表面审计另报；不能把厘米表面误差写成人体中心精度或统计搜索收益。

## 4. 起飞前置与阶段启动

原PX4桥剔除新增诊断字段后AST与Stage31相同。GroundOriginWindow保留静止3秒、≥50样本、速度≤.08、间隔≤.1、范围≤.12及status新鲜度等条件，只导出实际清空原因/次数、样本跨度、速度和grounded子门。

运行器先启动Gazebo/PX4、桥接和独立记录，等待真实原点校准＋新鲜估计Odometry，才启动映射、原生RACER、执行器、感知与视频，避免启动阶段提前叠加负载。此顺序是否解决两人场景问题，以新动态结果为准。

- 120墙钟秒或30仿真秒还没有合格原点/估计odom，退出并保存，不再等1200秒。
- 180墙钟秒或60仿真秒内要求已测得起飞或执行器ready，且armed/offboard。已测得起飞指同一新鲜估计坐标下相对首点z增加≥.3米，仅为运行器观测判据，不改变任何控制指令/门限，不等于真值飞行证明。
- 完整三高度启动旋转另报，不能因慢仿真下已在飞行的旋转尚未完成，错误地报“未起飞”。
- 原bootstrap跟踪监测、执行安全和全轮600墙钟秒看门狗继续生效；运行错误停止余批。

净空.6米、跟踪管.1米、制动触发.05米及名义v/a=.300/.400未改。三高度旋转仍是附加执行器策略，不冒称RACER原生要求。

## 5. 记录器和异常覆盖

独立Gazebo评测记录器在Python解释器尚存活时明确unsubscribe，阻止新回调、等待活动回调有界排空，再flush/close文件并释放原生节点；导出状态与写入计数。真实消息的SIGINT/SIGTERM退出夹具通过。

Stage31的SIGABRT在本次有效旧实现对照中未重现，具体C++退出根因仍未唯一确定；不称已证明根治。运行器保留清理前和清理后的每个直接进程退出码，清理时SIGABRT/SIGKILL等异常进入unexpected_exits/error；新core移到本轮证据。不能再用主循环内空unexpected_exits概括整个退出过程。只清理本轮拥有的PID。
