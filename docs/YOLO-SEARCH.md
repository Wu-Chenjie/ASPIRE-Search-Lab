# NBg 人员搜索（验收范围 A）

用户明确选择A：NBg已通过的跨区域探索作为本轮前置门槛，继续真实YOLO与扫描人体。GLAQ/CFV保留几何限制，不改变门宽、地图、0.3 m体素或0.6 m净空，不宣称多场景泛化。以下为当前实际工作记录；最终飞行汇总以代码树外`search-audit.json`为准。

## 固定模型与实际静态验证

官方YOLO11n-seg/Ultralytics 8.3.228，CPU PyTorch 2.5.1，conf=0.35、imgsz=640、原分辨率实例掩膜；版本/权重SHA、35项依赖锁和Artec扫描资产许可见[准备记录](SEGMENTATION-PREP.md)及`requirements-segmentation.lock`。选择依据是轻量ARM兼容和固定版本，不是最新型号。依赖只注入独立感知进程，RACER、控制、地图节点沿用原环境；关闭联网、遥测和自动安装。

- 原遮挡板夹具：扫描人体完整可见/部分遮挡/侧移显露各检出并有效定位，完全遮挡未检出；实际移除人体的四视角负例无误检。跨视角为一个确认目标。
- NBg原有门框：人体固定于生成器指定位置，未增加遮挡板、未更改扫描网格。完整显露、严重部分遮挡、初始隐藏、侧移显露及空场景各实际采集30对配准RGB-D（320×240）。这些相机是手动静态夹具，不能称自主搜索。
- 独立目标网格射线核验：最终严重部分遮挡视点仅16.20%目标投影像素的深度与人体一致；YOLO置信度0.592，二维候选保留，但因门框混入而拒绝三维定位（`ambiguous_depth_span`）。完全隐藏为0可见像素且无检测。显露后有效定位并跨视角确认。4 cm深度一致标准下完整视角约95%可见，投影未出画；数值还受栅格边缘与渲染采样影响。
- 前两轮相机试位保留：最初“partial”实际上全遮挡，下一轮约96%显露，都未当作严重部分遮挡通过。最终没有为适应该视点降低置信度或放宽深度过滤。
- 早期评测把每个部分遮挡候选都能定位设为强制条件，严重遮挡因此报告失败。按本任务“深度不可靠时保留二维、不得造三维”的要求，后续显式报告`localized_count=0`及拒绝原因，不将其改成定位成功；初始失败报告保留。

## 在线接口和时序

`person_search.node`订阅原RGB-D、CameraInfo、采集时刻TF和估计里程计；不读目标位置、扫描网格或评测真值。

- `/search/semantic_candidates`：真实框、分数、采集戳、二维存在与可选三维位置；无效深度/TF/过期时`xyz=null`。
- `/search/tracks`、`/search/targets`：只接收已验证位置，原跨视角去重与确认门槛保留。定位为可见表面，不是人体中心。
- `/search/detection_image`：原图叠实际YOLO框/掩膜，黄色未定位、青色已定位；确认状态另见地图绿色标记。
- `/search/perception_timing`：推理实际耗时、采集戳、处理时消息年龄及接受/拒绝原因。证据目录另存精确RGB、mask、bbox、score以及被接受帧的深度/K/采集时刻相机到地图变换。

首次飞行暴露“总挑最新图像，遗漏稍早已配对图像”的拒绝问题。后续修复挑选最新且已有估计位姿括号的帧，并将里程计订阅队列加到100以保留CPU推理期间的样本；40 ms括号间隔不放宽、不外推。耗时推理使用独立互斥回调组，两个ROS执行线程允许传感器、里程计、TF和时钟在推理期间继续接收；输入队列及位姿快照用锁保护。每轮只推理一个选定帧。0.75 s过期检查同时检查仿真时间差和从RGB接收开始的单调墙钟耗时，避免单线程推理期间ROS时钟回调滞后掩盖耗时。拒绝三维时二维证据仍保留。

旧MakeHuman/HOG夹具的真实YOLO置信度0.859，但掩膜深度跨度不可靠，三维被拒绝；该失败保留并成为真实ROS回归的“二维保留、三维为空”用例。HOG原回归与真实Artec有效定位用例分开，不通过伪造位置让测试通过。

## 运行与证据口径

本机容器`annual-px4-research`，源副本`/tmp/racer-search-task3-stage8-clean`，已验证RACER构建`/tmp/racer-search-task3-native-stage9-inflation/install`。保留原`/planner`只读。沿用[基座环境命令](HM3D-DIAGNOSIS.md)设置ROS/PYTHONPATH后：

```bash
python3 -m tools.flight.run \
  --prepared /tmp/racer-stage11-nbg-person-flight-scene \
  --detector yolo11n-seg \
  --segmentation-weights /tmp/racer-stage10-assets/yolo11n-seg.pt \
  --detector-python-path /tmp/racer-stage10-python \
  --stop-and-plan --recover-no-path --budget-clock sim --seconds 300 \
  --record-video --rviz --output NEW_RUN
python3 -m tools.hm3d.flight_audit NEW_RUN
python3 -m tools.flight.search_evidence NEW_RUN --video-output NEW_VIDEO_DIR
```

运行目录必须新建。飞行用正常原生探索，未手动指定人体观察点、未启用目标复查、更未根据真值移动相机。`continuous-rgb.avi`是实际持续订阅录制，源时间戳另存；`search-replay.mp4`则明确标为**实际推理帧日志回放**，4倍仿真时间、缺帧保持、不插值。所有框/掩膜取自保存的模型原输出，路径与目标标记来自在线估计/状态消息，不绘制真值。真值只在独立误差及碰撞评测中读取。

首次正常探索在169.888 s产生二维候选，175.960 s得到两个分离视角的track 1确认；初始隐藏期间没有候选。300 s仿真预算内10次轨迹激活及10次观测完成，独立评测1个正确确认、0个错误确认、就绪后0接触、无锁存飞行故障；跟踪误差P95为0.0640 m。确认后停留导致全程最大完成间隔123.38 s，不能称300 s持续探索。仿真仍使用GNSS辅助EKF2，不能当作无GNSS室内定位或实机验收。

第二次重复运行在84.088 s记录PX4锁存保护并随后降落，未当作搜索通过。ULog的`offboard_control_signal_lost`在84.060 s置位，电池`warning`始终0；不能根据蜂鸣日志中的“battery warning”误判为低电量。桥接在保护前反复报告`awaiting_heading_alignment`，PX4源码确认状态标志约每1 s仿真时间发布一次，慢速仿真可能超过3 s墙钟新鲜度限制；PX4内部姿态和位置仍持续更新。第二次没有直接记录标志接收年龄，因此显示负载是待验证原因，不把推断写成已证实因果。保留原0.5 s失联保护、3 s状态墙钟检查及40 ms姿态括号。第三次验证仅把RViz显示改为5 fps、点云保留0.3 s，降低软件渲染负载；新增状态年龄记录，运行器在锁存故障后立即结束。地图输入、传感器频率和规划安全边界不变，是否改善以重复运行记录为准。
