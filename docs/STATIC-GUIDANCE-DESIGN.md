## 已核查的代码事实

1. `presence.py:PresenceTracker.observe_rgb` 的 `rgb_hits` 仅接受 >=.70；
   `registry_evidence.py:batch` 却把它作为导航 `support_captures` 发出。
   `target_registry_methods.cpp` 使用 >=.50 / 3 帧 / .4 秒：存在真实耦合。
2. `DiscoveryMemory.observe/alias` 共享组 `epoch`，新 cue 会继承旧窗；
   `reason` 还用 2 秒 capture lease 和 20 秒 value window 限制行动。
   这不是静态目标不存在的证据。
3. `TargetRegistryROS.local/tick -> on_update -> taskRegistryUpdate`
   目前只更新缓存；重评分在 `planExploreMotion` 中执行。
4. `BearingBias.choose` 在评分前应用 1.5 倍门；
   `bearing_methods.cpp` 的诊断和 reachable 统计也重复该门。
   修改必须覆盖三处，不能只改选择器造成审计口径不一致。
5. 原生 FSM 已有执行中从未来 p/v/a/yaw 边界规划的分支，但最新 WSL C2
   另有五改二增，Mac Git 源并不包含完整活动构建。原 200ms 安全延迟
   故障仍未解决。当前不能宣称可直接部署新抢占链。

## 实施增量

### S1 共同证据合同（本阶段接入）

增加独立 NavigationConfig 和 nav_hits。使用原 >=.50、3 帧/.4 秒，
不调整 >=.70、5 帧/.8 秒的最终视觉确认门。连续支持是测量合同：
重复/乱序不增计数，实际 RGB 未匹配可中断连续序列，但不删除已确认身份
或静态假设。无新帧不生成负证据。导航报告和 registry 协议共用 nav_hits。

协议保留 schema 1 数字/字段布局，增加明确 support_policy 文本；
旧数据按其来源版本解释，不能把旧 support 字段回称新语义。
原生 packet 和 registry 使用同一 `bearingNavigationSupported` 谓词，
统一沿用 packet 原有 1ns 的 .4 秒跨度浮点容差，避免恰 .4 秒时两个入口
得出不同结论。此容差不改捕获时效、安全或轨迹门。

### S2 有界任务调度与静态假设（本阶段组件）

实体关联仍由原 registry 决定；调度器只接受其 canonical ID，不再扫描
图像或两两空间匹配。一个实体至多一条 pending，至多一条 in-flight；
全局在途资源上限单列，默认组件合同为 1。显式 alias 合并不重置预算，
在途合并后不能并发再开同一实体任务。

请求保留最早请求时间、资格上升版本和原因集合，即使最新快照不可见，
也不吞掉此前短暂的资格事件。普通续帧不是新任务版本；只在已定义的
实质状态变化时递增决策版本，避免每帧使计算作废。新版本在途时合并，
旧版本完成不能覆盖新状态。队列满/重复/完成失效/审计丢弃都可见。

静态假设没有按时间删除的入口；当前测量 lease 与历史假设分开。
负证据需要同一捕获的视锥、距离/成像有效、已知无遮挡和覆盖整个假设区域。
UNKNOWN 不等于 CLEAR；一次漏检只记一次有效失败，不宣布不存在。
确认事件撤销主动任务但保留身份。这里只实现/验证组件；
尚未接入原生地图、ROS 调度和执行器，不把组件结果称闭环。

### S3 episode、重获和原生事件链（后续）

独立新 cue 的 source/session/counter/capture 建立 episode，不继承身份年龄；
新帧不刷新 episode，重获条件须在验证集上冻结。原累计行动账本按
action_id 归并；保留已用代价和有效观察，不把无帧/遮挡计为失败访问。
复用 ID 查找，空间候选仅由原 registry 在必要时检索。

把 S2 接到 canonical registry 回调和统一任务调度，先轻量评分，必要时
才请求原生规划。事件唤醒不等旧航段结束，但安全旧轨迹继续执行。
提交绑定 evidence/map/ledger/plan generation；新轨迹在同一 switch_stamp
核验 p/v/a/yaw/yawrate、动态限制、已知自由走廊、原执行器授权和安全储备。
超时重新取初态或桥接，不只改时间戳。安全事件不受经济滞回阻挡。
不在感知回调格式化大日志/写盘。必须在最新 C2 共同栈上原生编译和接口测试。

### S4 价值与预算（后续）

先显式排除安全不可行，再完整计算探索基线和引导动作的收益差、额外运动

才允许较大绕行；数值经独立验证选择。收益是 score，未校准前不称概率。
已确认实体收益为零，仅顺路更新地图。不可在加负收益前沿用非负惩罚剪枝。
