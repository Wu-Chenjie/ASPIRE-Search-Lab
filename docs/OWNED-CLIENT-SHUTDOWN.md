# Stage43：拥有桥接后代的退出

2026-10-18。只改`tools/flight/gazebo_shutdown.py`的退出钩子；所有飞行/感知/规划/确认/地图/动力学/安全模块、运行参数和原生代码与Stage42逐份相同。

安装的ros2run在捕获KeyboardInterrupt后继续等待原生子进程，假定终端也向子进程发送信号。原PID-only预停未满足此假定，三轮均有sensor_bridge包装器未退出。实际无GZ/PX4反例证实根和子桥都活；补发拥有后代后两者正常退出，分支外哨兵未受影响。

新钩子先保存拥有客户端根及后代的PID出生身份，逐一核验并SIGINT，保留已知后代被重新挂父的所有权；等待实际静止后才公开停Gazebo。客户端包括独立评测订阅者，后者只写真值文件、不向算法发布。客户端等待上限2秒和公开停服均从原8秒非显示总清理预算扣除；未静止则跳过公开停服，仍由原有界SIGINT/强杀回收且异常照报。外部进程不触及、Xvfb仍延后，不延长任何飞行/清理验收时限。

该改动只在finally退出阶段执行。后续新比较可复用Stage42真实已通过的独立G01身份/飞行证据，须先核验全部飞行代码一致及新退出组件/回归；两比较组仍用同一新源码、逐轮完整验退出，不改写旧P01-B失败。它不是Gazebo底层唯一锁根因证明或全程安全证明。
