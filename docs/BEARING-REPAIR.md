# Stage27 · Stage26零效用根因与最小修复

2026-10-16（UTC）。诊断先于修复及新动力学试验。原stage26源码与1879个运行证据保持原样；本轮只移除了逐文件核验后、已有持久归档的两个容器临时重复目录以释放空间，记录见stage27-verified-cleanup.json。

8次有分数的原生决策、12组新鲜候选/方位组合，首个零项全部是“候选导航端点在人体像素圆锥外”：端点夹角49.77°—107.70°，圆锥半角13.52°—13.85°；对应相机yaw还全部背离人体方位（例：155.57°而支持界约50°）。这不是增加权重能修复的问题：乘积已经为0。旧实现把机体导航端点当成了应落入人体图像射线的点，却没有生成朝该方向观察的本地视角。

同帧TF光心差为0；射线反投影回截断后检测框中心误差最大2.85e-14像素；RGB与深度的光学变换相同，光学Z经固定四元数映射为机体X正向。map与原生world输入沿用相同坐标，没有规划比例对空间坐标缩放。新鲜组合的首次原生接收龄期0.132—0.272秒，决策时最新方位可低至0.284秒；10秒以上的“最新接收龄期”是旧线索再发布的龄期，不能误当首次端到端延迟。持续支持、置信度和时间基本门均通过，不是本例首个零效用原因。

每个原生日志中实际保存的候选及当时所有方位的捕获/首次接收/再发布/决策时刻、坐标、光轴、角差、角度项、yaw门、置信度、龄期衰减、覆盖、收益与原始/偏置代价见stage26-candidate-diagnosis.json。31次决策中另19次无新鲜方位、4次60秒预算耗尽。旧版本在进入分数日志前就过滤了其余顶层前沿，没有保存完整被过滤池；不能捏造其历史坐标，也不能据此宣称地图不存在安全观察点。

最小修复分两部分：保留同一50%折扣上限和1.5倍到达成本上限，用候选相机朝向与世界方位的夹角、原相机水平视场、侧向基线形成“定向观察机会”启发式，取消导航端点必须落在人体像素锥内的错误前提；原生端另加左右各0.6米、当前高度、面朝方位的至多两个本地观察候选。它们是观察位置，不是人体位置或假定人体距离；不预测必然可见。候选依旧通过原生已知自由/膨胀地图、原A*、原轨迹和原执行安全门。

新效用为`confidence * heading_alignment * (.5+.5*min(lateral_baseline/.6,1)) * (1-age/20)/(1+coverage+uses)`；射线方向保持原值，未扩张检测框圆锥、增加折扣或放宽净空。该量只是注意方向和视角变化机会，不是存在概率或已证明的可见性增益。无需深度即可选择观察，随后必须用真实新图像判断是否有新证据。

每个池中候选（包括零效用、不可达、未评估）现在记录来源、目标/yaw、各项收益与拒绝门；每次决策另记不加折扣时会选哪个候选。若本轮由候选生成而非折扣改变排序，应据实区分。规划结果标注选择是否被恢复分支覆盖；必须关联实际执行token和新采集图像才能称最小闭环通过。

单元测试在有区分度且已给定可行的候选集中检验正收益折扣能够使原始成本12的朝向候选优于成本10原目标，背向成本7候选不获奖励；原目标已同向时保留原目标也能有正效用。新增真实原生点云地图夹具再验证候选可达、原A*、原轨迹与原执行门，fixture没有实际飞行。新动力学按protocol.json限定一对开关，和确认收益分层验收。
