# 可关闭主动确认（阶段 20）

新增 `--active-confirmation`，默认关闭。它同时启用原生 RACER 的 `active_review` 接口；基线继续使用原检测器与旧确认逻辑。新模块不是探索规划器，不读取场景真值。

5 秒内至少 3 次有效视觉定位形成线索，可排队最多 30 秒等待安全停点；候选点只来自已观测深度，原 RACER 与执行器继续检查完整轨迹。必须看到新执行 token 的真实运动、匹配终点及观测完成证明，再用到达后的新鲜 RGB-D 确认。起飞垂直运动不能直接确认。无可靠深度保留二维候选，超时或耗尽重试保留 `unresolved`，不解释为无人。

原生调度修复：新鲜复查可越过恢复等待并唤醒 IDLE；接收时消息年龄仍须 ≤1 秒，接收后最多排队 20 秒，开始规划前重新检查原生地图的 FREE 与膨胀占据。不抢占未完成执行或返航。恢复预算、安全净空与未知空间规则不变。阶段 19 的远端探索失败还涉及执行器拒绝缺少已知自由空间的完整停止轨迹，此调度修复不能独自证明远端探索已解决。

## 运行与证据

在本机 `annual-px4-research` 容器的隔离源目录中，沿用 Jazzy、锁定 ROS2 RACER、PX4 和 YOLO 权重。源码快照、构建、日志及视频均在 `/tmp/racer-stage20*`，原工程只读保留。

```sh
source /tmp/racer-stage20/setup-v5.sh
bash /tmp/racer-stage20/flight-v5.sh \
  --output /tmp/NEW-RUN \
  --prepared /tmp/racer-stage20-k1cup-person-30hz-scene \
  --active-confirmation --seconds 180 --wall-watchdog-seconds 900
python3 -m tools.flight.active_review_audit /tmp/NEW-RUN
python3 -m tools.flight.search_evidence /tmp/NEW-RUN
```

基线省略 `--active-confirmation`；无人负例使用 `negative-30hz-scene` 并加 `--negative`。同一场景的相机内参、320×240 分辨率、人体位置和扫描几何保持不变，新副本仅将 RGB 与深度共同设为 30 Hz。30 Hz 仿真采集不等于墙钟实时运行，必须检查实际源时间戳。

视频采用一条真实 RGB 消息对应一帧；检测结果仅画在它自己的推理帧小窗中，注明原时间戳、年龄和更新频率。地图小窗为估计 XY 轨迹与在线目标，不是占据地图或真值。轨迹标签是算法判断，正确率需独立评测。
