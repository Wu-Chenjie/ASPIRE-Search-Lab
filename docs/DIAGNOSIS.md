## 原生异常：已复现、修复

固定根点 `(0,0,1.8)`、目标 `(1.2,0,1.8)`、终点偏航0。修复前诊断：位置优化33维、间距0.109062；偏航优化15维、间距**0**、初值均有限。`calcSmoothnessCost()` 把控制点三阶差分除以零间距，得到NaN。`nlopt::opt::optimize()` 抛出 **`std::runtime_error("nlopt failure")`**；对应本机 `/usr/include/nlopt.hpp:127`。原代码捕获异常后继续索引空的 `best_variable_`（长度0，最小代价仍为DBL_MAX），最终SIGSEGV，进程返回-11。这里给出对应函数和实测诊断，不冒充已有调试器栈回溯。

精确改动在 `tools/flight/optimizer_overlay.py`，只作用于新构建副本：

- 常量信号的零间距使用非归一化平滑项，保留合法常量偏航。
- 优化前检查维度、有限性、时间间隔、边界状态、路点索引及预算；每次清空旧最佳解。
- 检查代价、梯度和求解结果；异常及无有效解向上传播，不吞错、不复用旧解伪报成功。
- `planTrajToView()` 捕获失败并返回 `FAIL`；事务回滚恢复上一条完整提案，避免位置成功、偏航失败时留下半条新提案。
- 拒绝非有限、越界、零位移及未观测自由的根点/目标。受控观测缺口测试发现原A*终点接近判定可能接纳未知目标；现在入口即拒绝，原执行器检查继续保留。

没有修改控制器、地图安全余量或执行器硬限。固定低间距处理之外的普通平滑项不变；新增拒绝可能减少提案，不能声称飞行性能改善。

## 规划限制是否过宽

此前两配置同时改变了多个因素：

| 类别 | consistent | bounded-fast | 作用 |
|---|---|---|---|
| RACER名义速度/加速度/jerk/偏航率 | .30/.40/4/.325 | .45/.60/4/.40 | 路径时长、优化软惩罚及部分搜索约束；不是执行安全证明 |
| 原生视点评价速度/加速度/偏航率 | .30/.40/.325 | .45/.60/.40 | 会改变视点代价与选择 |
| 执行器硬限 | 1/1.2/4/.9 | 1.2/1.5/4/1 | 连续曲线超限即拒绝；旧两组硬限也不同 |
| 静止端点钉扎、受限时间缩放 | 关闭 | 开启 | 特定条件才生效；旧飞行时间缩放均未触发 |

两组 `min_time=false`；不能把旧非严格配对飞行的变化归因于速度一个因素。

本轮固定观测地图、根点、目标、零初速度及执行器硬限1/1.2/4/.9，固定视点评价参数，只改变指定输入。完整观测各组地图SHA一致：

| 单变量 | 实测结果 |
|---|---|
| 修复前速度 .30→.45 | 两者均-11崩溃；不支持“较宽速度上限是本次NaN根因” |
| 修复前仅偏航终点0→.3 rad | 从崩溃变为成功，符合零间距根因 |
| 修复后速度 .30→.45 | 均成功；时长8→5.333 s、速度峰值.276→.386 m/s，均通过相同硬限 |
| 修复后加速度 .40→.60 | 此低加速度样例的曲线完全相同；不代表其他工况无影响 |
| 非零偏航仅增加端点钉扎 | 位置曲线及地图SHA不变；起/终偏航率由-.0030/.0179变为约0/0，内部峰值由.0179增至.0707 rad/s；软约束下终点实际仅.04696 rad，钉扎后为请求的.3 rad，均通过硬限 |
| 同一目标，仅遮去前向观测扇区 | 未知目标可靠失败；完整观测成功 |

该对照隔离了本次异常和约束作用，**没有证明旧探索停滞与规划上限无关**。旧4845次No path/约99秒日志证实无路重试缺口；初始地图/估计根点/前沿不同可能触发它，但现有记录不足以区分具体原因。重复未复现不是“原故障只是随机误差”的证据。

## 两次未确认：已有记录能说明什么

以下为仿真时间，离线复测使用与运行相同的OpenCV 4.6.0/HOG+SVM。模型/真实位姿只用于事后投影和可见性评测，误差容差0.08m；保存帧稀疏，统计不代表连续检测率。

| 环节 | consistent 左侧 | bounded-fast 右侧 |
|---|---|---|
| 首条真实人员线索 | 13.732 s | 11.752 s |
| 30秒TTL放弃 | 43.760 s | 41.912 s |
| 探索执行就绪 | 65 s | 69 s |
| 最终线上语义视角/复查次数 | 1 / 0 | 0 / 0 |
| 保存帧中人体可见≥100像素 | 16/34 | 9/35 |
| 人体未投影入画面的保存帧 | 18/34 | 26/35 |
| 估计总路径 | 24.76 m | 23.97 m |

- **覆盖/显露**：两组均有显露证据，不能称“从未找到可见视角”。一致组117.352秒有完整人体和HOG命中，线上同戳记录也有1个语义视角；积极组134.048/138.604/143.224秒分别有3532/5097/4419个可见人体像素，但人体下部被画面边缘截断。
- **检测与几何**：积极组35个保存帧HOG均未命中，故可见不等于被当前检测器识别。一致组126.920秒HOG评分2.94，但人体与背景连成30992像素组件，水平尺度7.005m，超过0.85m门槛，未产出深度候选；117.352秒对应组件水平尺度0.591m则通过。两保存视点相距1.263m，超过0.5m确认分离门槛；但126.920秒不是线上已记录的处理戳，不能断言这一帧若改变过滤就必然确认。
- **TTL与路线**：两组线索在起飞扫描完成前已放弃；放弃态不参与主动复查，实际目标轨迹的复查次数均0。因此这两次运行没有目标线索改变已执行路线的证据。TTL不会阻止以后累计到2个语义视角后确认，但确实关闭了线索驱动的复查机会。
- **定位/关联/阈值**：真实人员线索持续归于同一track 1，没有现存证据指向跨视角分裂作为主因；最终不足2个相距≥0.5m的语义视角是未确认的直接门槛。保存记录不足以逐帧排除定位/关联误差，也不能区分所有未保存时刻的遮挡、转向、截断和漏检。感知日志还有位姿括号/TF拒绝，日志按5秒节流，条数不等于丢帧总数。

0.85m过滤位于 `candidates()` 的**深度连通组件层**，RGB HOG框先计算，但只有通过该几何过滤的组件才被赋予语义标签并返回。因此深度组件被拒绝时，相应RGB存在性证据也没有独立候选保留；不是RGB分类器本身否认有人。当前实现确实把语义存在与三维定位过度绑定。

最小后续接口应拆为检测器无关的二维语义观测（bbox/score/stamp）与可选三维定位（valid/xyz/不可靠原因/原检测关联）。深度无效仍保留未定位线索，不填虚假坐标、不取框中心板深度；现有地图轨迹确认与安全执行继续要求有效几何证据。HOG和以后YOLO只替换二维检测适配层。上述分离尚未实现，本轮没有新增检测器。
